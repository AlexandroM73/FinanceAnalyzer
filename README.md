# Finance Analyzer — Система анализа финансовых транзакций


Простой инструмент для анализа расходов по категориям, дням недели и рабочим/выходным дням.


## Возможности


* Анализ расходов по категориям за последние 3 месяца.
* Статистика трат по дням недели.
* Сравнение расходов в рабочие и выходные дни.
* Автоматическое сохранение отчётов в JSON‑формате.
* Обработка ошибок с логированием.

## Основные функции
### ` spending_by_category(df, category, date=None)`

Анализирует расходы по указанной категории за последние 3 месяца.

* Параметры:

df — DataFrame с транзакциями (колонки: «Дата платежа», «Категория», «Сумма операции»).

category — название категории для анализа.

date — дата для расчёта периода (формат ГГГГ‑ММ‑ДД, по умолчанию — текущая дата).

Возвращает: DataFrame с колонками «Месяц» и «Сумма».

## ` spending_by_weekday(df, date=None) `

Показывает средние траты по дням недели за последние 3 месяца.

Параметры:

df — DataFrame с транзакциями (колонки: «Дата операции», «Сумма операции»).

date — дата для расчёта периода.

Возвращает: DataFrame с колонками «День недели» и «Средняя сумма».

spending_by_workday(df, date=None)

Сравнивает средние траты в рабочие и выходные дни за последние 3 месяца.

Параметры: те же, что у spending_by_weekday.

Возвращает: DataFrame с колонками «Тип дня» (Рабочий день/Выходной день) и «Средняя сумма».

` @save_report_to_file(filename=None) (декоратор)` 

Сохраняет результат функции в JSON‑файл.

Параметры:

filename — имя файла (если None, генерируется автоматически).

При конфликте имён добавляет суффикс _1, _2 и т. д.

## Покрытие тестами
Тесты покрывают следующие сценарии:

- Корректные входные данные.

- Отсутствующие обязательные колонки.
- Некорректный формат даты.
- Работа декоратора сохранения.
- Обработка JSON‑ошибок.
- Конфликты имён файлов.
